# P1 Journey on Real Data Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The prototype's five-stage journey (consult → decision desk → store radar → Plan B → pre-trip checklist + walk mode) and the landing page, running on the Starcoach data in the decision-8 look. This is the competition demo.

**Architecture:** Django Ninja serves four read endpoints and two write endpoints; the web ports the prototype's reducer, ranking and screens almost line for line, swapping `data/demo.ts` for a typed API client. Filtering, sorting and Plan B ranking stay client-side pure functions (≤ 40 rows per product).

**Tech Stack:** as P0, plus Playwright for the journey test, GSAP for the sheet and bars (decision 8 motion list).

**Spec:** `docs/PLAN.md` §2 (journey + honesty rules), §3 (pages), §4 (mapping), §5.1–5.3, §5.5. Prototype: `docs/torob-gard-ux-prototype/src/`.

## Global Constraints

- Look: `docs/design/brand/README.md` (decision 8): light only, `paper` + blush glow, white cards with no border and `shadow-card`, `orange` is the only active colour, black `panel` sheet for walk mode and the store sheet's decision area, Vazirmatn thin+bold mix. Prototype colours (`brand` red, `cream`, `mint`) are **not** used (decision 11).
- Copy: the prototype's Persian strings are the source; voice rules from the brand README (تو, warm, no «می‌باشد»). Remove every «نمایشی / سناریوی نمایشی / هکاتون» label except where the data really is a demo seed.
- Honesty rules 1–6 in `PLAN.md §2` apply to every screen.
- Phone first: designed at 390 px; touch targets ≥ 44 px; works in Bale/Eitaa webviews (no hover-only, geolocation and clipboard may be missing).
- Motion: GSAP, transform/opacity only, `prefers-reduced-motion` respected; only the four moments in the brand README.
- UI skills while building: `emil-design-eng` per screen, `apple-design` for the sheet, `mobile-native` before the gate, `break-ui` on ShopRow, TierCard and the walk sheet.
- API JSON uses snake_case; the web client maps to the prototype's camelCase types in one place (`web/src/lib/api.ts`).

## Review Focus

1. Shop with no floor/unit (35% of shops) → radar row and walk mode say «شماره‌ی واحد ثبت نشده — از اطلاعات پاساژ بپرس» instead of blank or "undefined" (Task 9 + Task 11 tests).
2. `weekly_hours` = `{}`, a day with `status: "closed"`, or a shift ending after midnight → open-now is `null` / `false` / correct, never a crash (Task 5 tests).
3. Geolocation denied or unavailable in a webview → radar falls back to the default anchor «مترو سعدی» and says so (Task 9 test).
4. User types a budget in Persian digits («۱۵ تا ۲۵») or a category the desk doesn't cover («چراغ آشپزخانه») → reducer still advances; desk shows the designed empty state (Task 6 tests).
5. Every shop for the model has failed in Plan B → `diagnoseNoAlternative` copy and a way back to the desk, no empty list (Task 10 test).
